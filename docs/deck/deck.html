The problem

One phone layout. Four very different people.

Phones are designed for an average user who does not exist. Settings that could help are buried, and nobody adjusts them for the people who need it most.
Senior

Halina, 78

Tiny icons, missed taps, forgotten pills. A "your grandson needs money, right now" call nearly worked.

Kid

Zosia, 8

Too many choices and endless feeds. Homework, a focus timer and "call Mum" would do.

Low vision

Michał

Small targets and silent screens. Needs fewer, larger tiles and everything read aloud.

Everyday

Daniel, 29

Plans spread over five chats. "Dinner Friday, vegan, under 80 zł" should be one tile with a vote.

Accessibility settings exist, but they are one-size switches. Nothing looks at how this person actually uses the phone and adapts, with family in the loop.

The solution

A home made of live tiles, generated for you

Live, actionable tiles

Each tile is a tiny card that does one thing: "Pills 8:00, tap when taken", "Call Kasia", "14° and rain, take the umbrella", "Homework 3 of 5". Big, colourful, readable aloud.

Ask Tiles

Type a request in English or Polish. The assistant answers with new tiles, not paragraphs: a reminder, a call shortcut, a dinner plan with vote buttons.

Adapts, family approves

Missed taps and unused tiles become suggestions ("text 40% bigger?"). For seniors and kids, a caregiver or parent approves every change first.

TileSpec, TileBlock, TileAction, Profile, Suggestion, ComposeResult: one fixed contract between generator and renderer.

Composer: deterministic EN/PL intent planner → 1-3 TileSpecs + reply + follow-up chips. Adaptation: usage signals → suggestions. Guardian: red-flag rules.

TileStore singleton (AppStorage, persisted with Preferences); approvals queue; tap recording. Platform services: widgets, notifications, reminders, read-aloud, haptics, dialer.

Reproducible · honest · next

From a clean checkout to a running app

git clone https://github.com/JustAnotherDevv/tiles-hackyeah-2026 cd tiles-hackyeah-2026 # no Huawei ID: OpenHarmony SDK + its debug keystore source .toolchain/env.sh # README section 4.1 scripts/build-ohos-signed.sh # -> release/*.hap hdc install -r release/<signed>.hap hdc shell aa start -a EntryAbility -b com.hackyeah.tiles
  • Minimum API 20, compiled against API 24; ordinary-app permissions only.
  • Honest AI: the assistant is a deterministic on-device planner, not an LLM. Development used Claude Code; see AI_WORKFLOW.md.
  • Simulated and labelled: Guardian demo call, "Kasia's phone", weather and plan options. Reminders fire only while the app runs (no AppGallery entitlement).
  • Next: an LLM generator behind local guardrails, a real caregiver device via distributed data, call screening on a device.
